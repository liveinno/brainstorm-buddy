# BrainstormBuddy — гид по главному экрану

> Обновлено: 2026-07-04, соответствует сборке ветки `feature/chatlog-restore`.
> Это пользовательская документация оверлея: все кнопки, контекст-меню, эквалайзер.
> Для агентов: описания соответствуют обработчикам в `OverlayWindow.xaml(.cs)`.

## 1. Тайтлбар

Перетаскивание за любое место полосы = переместить окно. **Двойной клик = сквозной режим** (см. «Глаз»).

| Элемент | Что делает |
|---|---|
| Селектор промпта | Мгновенно меняет роль LLM (Собеседование / Совещание / …). ВНИМАНИЕ: сбрасывает весь диалог — историю LLM и счётчик токенов (новый промпт со старым контекстом даёт кашу, так задумано) |
| Чип **REC** / Чип **LLM** | Индикаторы, не кнопки: пульс красным = идёт запись, пульс синим = ждём ответ LLM. Оба серые = пауза |
| Робот | Пауза LLM (`Ctrl+Shift+Y`): аудио и распознавание продолжаются, ответы не запрашиваются. Удобно на NDA-темах |
| Пауза ‖ | Пауза аудио (`Ctrl+Shift+P`): полная остановка захвата звука |
| Шестерёнка | Настройки (`Ctrl+Shift+S`) |
| Автоскролл ↕ | Вкл/выкл автопрокрутку истории к новым ответам (выключен — иконка тускнеет) |

## 2. Тулбар

| Элемент | Что делает |
|---|---|
| Слайдер **ТИШИНА** (0.4–10 с) | Пауза в речи, после которой реплика уходит в распознавание |
| Слайдер **ЧАНК МАКС** (8–120 с) | Максимальная длина куска аудио — страховка на непрерывную речь |
| Молния (жёлтая) | Отправить сейчас: не ждать паузу, немедленно отдать накопленное аудио в STT |
| Экспорт | Сохранить весь транскрипт беседы в файл |
| AI-протокол | LLM составляет протокол встречи: тезисы, решения, action items |
| Камера | Режим скриншота (`Ctrl+Shift+C`): временно показать окно в захвате экрана — иначе оно невидимо в OBS/Zoom и на скриншотах |
| « · ↺ · » | Пресеты темпа речи: медленнее (пауза длиннее) / сброс к 1.8с·60с / быстрее |
| Глаз | Сквозной режим: клики проходят «сквозь» окно в приложение под ним. **Выход — только двойной клик по тайтлбару** (единственная «опасная» кнопка) |
| Корзина (красная) | Очистить историю и начать новый чат: сбрасывает контекст LLM и счётчик токенов |
| Крест (красный) | Скрыть оверлей (вернуть: `Ctrl+Shift+H`). Приложение продолжает слушать |

## 3. История вопрос-ответ

Каждая пара: **ВОПРОС** (распознанная речь, mono-тайминги `←STT · длительность`) и карточка
**ОТВЕТ** с суммарной задержкой Σ (зелёная <1.5 с / жёлтая / красная >3.5 с).

Точка слева у пары: синяя = отправляется, зелёная = готово, красная = ошибка.

При включённой диаризации у пузыря вопроса рисуются чипы спикеров: одна реплика может
нести несколько меток `[S1] [S2] …` (собеседники перебили друг друга внутри одного куска)
— тогда чип показывается на каждого. Правый клик по любому чипу → «Назначить имя…»
(алиас действует на всех пузырях текущей встречи).

Дополнительные блоки при мульти-агентах:
- синий **HRD СОВЕТ** — совет HR-агента (появляется только на soft-skills темах, иначе агент молчит);
- янтарный **ЗАЩИТА** — реакция на давление/манипуляцию в разговоре;
- золотой **РАСШИРЕННЫЙ ОТВЕТ** — появляется после «Ответить расширенно».

### Правый клик по паре — контекст-меню

| Пункт | Что произойдёт |
|---|---|
| Копировать всё | Вопрос + ответ в буфер обмена |
| Копировать вопрос | Только распознанный текст |
| Копировать ответ | Только ответ LLM |
| Ответить расширенно | LLM отвечает подробно — под парой появляется золотой блок |
| Сбросить расширенный ответ | Убирает золотой блок |
| Фокус на этой паре | Зелёная рамка — пометить важное (фокус только у одной пары одновременно) |
| Снять фокус со всех | Убрать рамку |

## 4. Эквалайзер (лента АУДИО)

Лента последних 2 минут звука: один бар = полсекунды, новое появляется справа, старое
уезжает влево. Клик по заголовку **▾ АУДИО** сворачивает ленту (шеврон меняется на ▸),
состояние запоминается между перезапусками. Под лентой — шкала абсолютного времени
(HH:mm:ss каждые 10 секунд), фазы сопоставляются с mono-таймингами в карточках истории.

### Цвета

| Цвет | Значение |
|---|---|
| Розовый `#F87171` | Идёт живая речь; высота бара = громкость в этот момент |
| Синий высокий `#60A5FA` | Реплика вырезана и отправлена в распознавание — STT работает |
| Зелёный высокий `#4ADE80` | Ответ LLM получен и показан в истории |
| Тускло-бордовый `#9C5A5A` | Звук есть, но система в простое (фон/музыка между репликами) |
| Серые пеньки `#3A4653` | Тишина ниже порога VAD; при паузе лента тоже плоская |

Цветовая логика едина по всему окну (точки статусов, чипы, эквалайзер):
**розовый/красный = вход, синий = обработка, зелёный = результат.**

### Что это даёт: диагностика одним взглядом

| Вопрос | Как ответить по ленте |
|---|---|
| Звук вообще пишется? | Люди говорят, а лента плоская → проблема с микрофоном/лупбэком |
| Реплика дошла до конца? | После розового должен появиться синий, потом зелёный. Розовый есть, синего нет → VAD не режет (речь без пауз — жми молнию). Синий есть, зелёного нет → упал STT или LLM |
| Какая задержка? | Расстояние розовый→зелёный на шкале времени = сколько секунд ждать подсказку |
| Порог VAD верный? | Тихая речь красится тускло-бордовым, а не розовым → порог RMS завышен, крутить в Настройки→Аудио |
| Пауза не забыта? | Лента внезапно плоская при живом разговоре → ты на паузе (чипы REC/LLM серые) |

## 5. Футер

| Элемент | Что делает |
|---|---|
| Токены: N (in/out) | Суммарный расход токенов LLM за сессию, включая всех агентов |
| Часы | Текущее локальное время (mono) — для сверки с таймингами |
| Поле «Секретное сообщение в LLM…» | Ручной вопрос LLM с меткой `[secret]` — обрабатывается приоритетно. Отправка: Enter или круглая кнопка |

## 7. Караоке-оверлей и история встреч (коротко)

**Караоке** (`Ctrl+Shift+K`, настройки — вкладка «Караоке»): отдельная полоса-телесуфлёр
у края экрана. Свежая реплика прижата к нижнему краю; при «Высота полосы» > 0
(жёсткая высота в % экрана) текст внутри прямоугольника можно прижать к верхней
кромке — настройка «Якорь текста» → Сверху (пустота уходит вниз). При 0=«по
контенту» полоса сама поджимается под строки, пустоты нет. Старшие строки
уезжают вверх и бледнеют.
Ролевые цвета: вопросы собеседника — розово-красные (`#FFF27A8A`), свежая строка — золотая
(`#FFFFE9A8`), маркер у неё — акцентный (`#FF4ADE80`), старые строки затухают к своему цвету.
Полный набор ручек (позиция, размеры, шрифт, глубина истории, стелс) — во вкладке «Караоке»
настроек и в руководстве пользователя (docs/manuals).

**Экран OCR**
Настройки → вкладка **«Экран OCR»**: чекбокс «Включить распознавание текста на
экране» делает фичу доступной (шар + хоткеи); отдельная галочка
**«Авто-слежение за экраном»** запускает фоновый `ScreenTextWatcher` — он сам
находит вопросы на экране и шлёт их в LLM. Они независимы: авто-слежение можно
выключить, а ручной снимок `Ctrl+Shift+N` продолжит работать (и даже при
выключенной фиче целиком — хоткей поднимает разовый проход).

**Шар-индикатор**: при включённой фиче в правом нижнем углу экрана висит
полупрозрачный круг 28px (скрыт от захвата экрана, клики проходят сквозь).
Цвета: зелёный — ожидание, синий — распознавание, фиолетовый — отправка в LLM,
красный — ошибка (3 с → назад). Отключается чекбоксом «Показывать индикатор».
Уже отвеченный вопрос повторно не шлётся — помнит последние ~16 отправленных.

**История встреч**: каждая встреча пишется на диск инкрементально (журнал
`%APPDATA%\BrainstormBuddy\meetings\*.jsonl`, переживает падение). Смотреть: вкладка
«История» в настройках или трей → «История встреч». В окне — транскрипт, AI-саммари
(протокол), копирование и выгрузка .txt.

**Диагностика для поддержки**: Настройки → «Диагностика» → «Собрать логи для поддержки»
→ zip в «Документы\BrainstormBuddy» (логи и конфиг обезличены; при падениях добавляются
crash.log, crash-last.txt и ui-hang.log — снимок зависания UI от сторожа). WER-дампы *.dmp
в архив не входят — README.txt внутри перечисляет, какие лежат в
`%APPDATA%\BrainstormBuddy\dumps` / `%LOCALAPPDATA%\CrashDumps`;
при повторном падении пришлите свежий отдельно.

## 8. Buddy Memory — долгоживущая память

ПО помнит собеседников, проекты, открытые вопросы и решения **между встречами** —
всё в `%APPDATA%\BrainstormBuddy\memory.db` (SQLite).

### Как включить
С 2.16.0 память **включена по умолчанию** — на чистой установке работает сразу:
и «Использовать в ответах» (подмешивать факты в LLM-запросы), и «Писать факты»
(извлекать знания из транскриба после встречи). Полная сборка (Full) несёт
локальную модель эмбеддингов в комплекте — ничего скачивать не нужно; в Lite
модель докачивается кнопкой на вкладке «Память». Управление: Настройки →
вкладка **«Память»** → чекбокс «Включить память» и переключатели чтения/записи.

Включение работает без перезапуска: как только нажата «Сохранить» в настройках, служба
памяти поднимается в работающем приложении — пункт «Память» в трее и чип в оверлее
становятся доступны сразу.

### Что умеет

| Фича | Где | Что делает |
|---|---|---|
| **Центр памяти** | Трей → «Память» или Настройки → «Память» → «Центр памяти» | 5 вкладок: факты (поиск, фильтры, pin, edit, удаление, цепочка версий), встречи (датированные, саммари, журнал), проекты, люди, фоновые задачи |
| **Спросить память** | `Ctrl+Shift+M` | Режим «Поиск» — релевантные факты со скором и scope-бейджем; «Ответ» — LLM отвечает только по памяти, показывает источники. Если фактов нет — честно «в памяти этого нет» без обращения к LLM. Ответ можно выделить мышью (вместе с таблицами и блоками кода) и скопировать `Ctrl+C`; если ничего не выделено, `Ctrl+C` после клика по ответу копирует его целиком, а в шапке блока «ОТВЕТ» есть кнопка «Копировать ответ». В буфер всегда идёт видимый текст без разметки |
| **Pre-call бриф** | старт записи | Окно перед встречей: заголовок по проекту, «последний созвон N дн. назад», топ фактов + открытые вопросы, редактируемая повестка, флажки «пользоваться/писать» |
| **Чип-память** | нижняя панель оверлея | Круглый индикатор: серый — выкл, жёлтый — только чтение или только запись, зелёный — read+write. Клик = переключить для текущей встречи |
| **Алиасы спикеров** | правый клик по чипу S1…S8 | «Назначить имя…» → чип показывает «Иван» вместо «S1» (только в этой встрече) |
| **Память по запросу ассистента** | голосом в встрече | «запомни, что…» / «забудь …» — модель отдаёт скрытую директиву, факт пишется сразу, зелёный тост (5 сек) показывает сохранённое. Работает при включённом «запоминать эту встречу» |
| **Извлечь в память** | окно «Транскрибация файла» | Кнопка 🧠 у готового результата → диалог со своими правилами извлечения → список фактов с галочками → сохранить выбранное |

В Центре памяти правый клик по факту открывает меню действий: «Показать источник»
(встреча и сегмент транскрипта, откуда факт взят), «Править…», «Сделать
неактуальным»/«Сделать актуальным» (история версий сохраняется), «Удалить…»
(с подтверждением, безвозвратно), «Сменить область»/«Сменить проект», «Добавить
тег…». Кнопки «Экспорт…»/«Импорт…» выгружают память в JSON или Markdown и
загружают обратно из JSON — проекты и факты переносятся целиком, дубли при
импорте пропускаются со счётчиком. Внизу окна строка статистики:
фактов · встреч · джоб в очереди.


### Настройки (вкладка «Память»)

- **Режим сохранения**: `off` | `summary` | `smart` | `full` — как подробно извлекать.
- **Режим проверки**: `automatic` (факты сразу активны) | `review` (окно проверки после встречи) | `manual` (только подтверждение в Центре памяти).
- **LLM для памяти**: `same` (основной провайдер) | `separate` (свой) | `disabled` (извлечение выкл).
- **Эмбеддинги**: `disabled` (только полнотекст) | `local` (E5 на машине) | `openai` (по API). Смена → авто-переиндексация фоновой job'ой.
- **Авто-рекол**: чекбокс + бюджет токенов (500–8000) и макс. фактов (1–20).
- **Retention**: транскрипты `never|7d|30d|90d|forever`, факты `forever|30d|90d|custom` — автоочистка фоном.
- **Активный проект** — скоуп для новых фактов и recall.

По **режимам проверки** подробнее: при `automatic` извлечённые факты активны сразу и
уже на следующей встрече попадают в recall. При `review` после остановки записи
открывается окно «Проверка памяти после встречи» — список извлечённого с галками и
кнопками «Сохранить выбранное» / «Сохранить все» / «Отклонить всё»; бездействие 30 с
= автосохранение выбранного, Esc/крестик закрывает без записи (факты остаются в
статусе «Ожидают»). При `manual` окно не показывается вовсе — всё извлечённое ждёт
вашего решения в Центре памяти.


### Приватность
Всё локально в `memory.db` рядом с конфигом; наружу уходит только текст промпта
извлечения — и то только когда включён LLM для памяти (по `ModelMode`).

## 9. MCP: права агента и подтверждение удаления

Настройки → вкладка **«MCP»** → «Подключить AI-агент»: мастер выдаёт внешнему
агенту (Codex, Claude и другим MCP-клиентам) доступ к данным Buddy по протоколу MCP.
Что именно разрешено, решаете вы на шаге «Доступ».

| Право в мастере | Что разрешает агенту |
|---|---|
| Чтение данных | Искать и читать встречи, память и вложения (`buddy_search`, `buddy_read_source`) |
| Добавление фактов | Записывать новые факты в память Buddy (`buddy_add_fact`) |
| Изменение данных | Править текст уже сохранённого факта (`buddy_update_fact`) |
| Удаление | Помечать факт удалённым (`buddy_delete_fact`) — и только после вашего подтверждения |
| Включать память | Даёт доступ к памяти Buddy; без этого флага инструменты памяти не работают |

- **Пустой набор прав сохраняется как есть.** Если снять все галочки, подключение
  создаётся без полномочий: Buddy не расширяет права сам, и агент не сможет ни
  читать, ни изменять данные. На шаге «Доступ» об этом показывается подсказка.
- **Права независимы друг от друга.** Добавление факта работает и без права на
  чтение — агенту не нужно видеть ваши данные, чтобы записать факт. Область
  данных (все проекты / только существующие / выбранные встречи) действует всегда,
  независимо от набора прав.
- **Права и область проверяются на каждом вызове:** отказ приходит ошибкой, а не
  пустым результатом — переспрашивать по кругу бесполезно.

### Удаление факта агентом — только с вашего подтверждения

Агент может удалить факт только если у подключения есть право «Удаление» **и**
вы подтвердили действие карточкой в оверлее Buddy. Отказ, отмена или отсутствие
ответа в течение 5 минут — удаление не выполняется, факт остаётся на месте, данные
не меняются. Само удаление мягкое: факт помечается удалённым и перестаёт попадать
в подборки, а сама запись в базе остаётся.

Токен и права выданного подключения видны на той же вкладке «MCP», любой токен
можно отозвать кнопкой. Пошаговое подключение к Codex — в руководстве
пользователя, глава «Подключение BrainstormBuddy к Codex».
