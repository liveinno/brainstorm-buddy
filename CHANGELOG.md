# История изменений BrainstormBuddy

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/).
Версии до 2.4.0 не тегировались в git — их границы восстановлены по истории разработки
и приведены для контекста (публично раздаётся только 2.4.0 и новее).

## [2.28.2] — 2026-10-11

### Изменено
- **Дефолтная длина ответа поднята до 1500.** `Advanced.MaxResponseTokens`
  400 → 1500 и `Ui.MaxAnswerChars` 1000 → 1500 из коробки: reasoning-модели
  (deepseek-r*/v*, o*, qwq) из 400 токенов тратили ~390 на скрытые размышления,
  и видимый ответ обрывался «…» (finish_reason=length, несколько слов вместо
  реплики). 1500 оставляет запас под размышления + развёрнутый ответ, а лимит
  символов в оверлее больше не режет типовой ответ.

## [2.28.1] — 2026-10-11

### Исправлено
- **Краш «begin meeting» в профиле без проектов.** Orphaned
  `Memory.ActiveProjectId` (проект удалён или профиль новый) ронял INSERT
  встречи на FK `mem_meeting.project_id → mem_project.id` — в лог шёл
  SQLite Error 19 каждый запуск, встреча не создавалась. Теперь id, которого
  нет в `mem_project`, сбрасывается в Global с предупреждением до вставки.
- **Память: жёсткая изоляция проектов при recall.** Чужой проект/персона
  раньше получали лишь мягкий штраф `ScopeScore=0.0` и при высоком косинусе
  векторной ветки всплывали поверх фактов своего проекта (утечка чужого
  контекста в PreCallBrief/Ask Memory). Теперь `MemoryRecallService` отсекает
  кандидатов не-видимого scope до ранкера — в FTS- и векторной ветке;
  Global-память по-прежнему применима в любом scope. Покрыто регрессионным
  тестом `Recall_ScopeIsolation_ForeignProjectExcluded`.

## [2.28.0] — 2026-10-11

### Исправлено
- **HttpClient.Timeout резал длинные запросы.** Клиентский таймаут 30с глушил
  весь OpenAiClient — включая TranscribeAsync с собственным дедлайном 300с:
  длинные аудио-чанки и медленные ответы локальных моделей обрывались на 30с.
  Timeout теперь InfiniteTimeSpan, дедлайны задаются только per-call linked CTS
  (Ask — requestTimeout/RequestTimeoutSeconds за попытку, STT — 300с на вызов,
  проверки/модели — RequestTimeoutSeconds на весь чек).
- **Таймаут больше не притворяется «нет соединения».** TaskCanceledException
  убран из IsConnectivityError; Ask при дедлайне попытки ретраит с новым CTS,
  исчерпав — «LLM-сервер не отвечает (таймаут)». Обрыв SSE-стрима по таймауту
  пишет таймаут, а не «поток прерван».
- **Фоновые LLM-вызовы не поднимают баннер здоровья.** AskAsync получил
  `background`/`requestTimeout`; memory-пайплайн (MemoryExtractor,
  MemoryConsolidator) помечен background:true с дедлайном 120с — их ошибки
  идут в лог, но не вешают юзеру «LLM недоступен».

### Добавлено
- **Отдельная галка для тех-меток у вопроса.** Настройки → Оверлей →
  «Показывать технические метки (STT / OCR / длительность аудио) у вопроса»
  (Ui.ShowQuestionTimingLine) — статус-точка и mono-строка глушатся ею,
  speaker-чипы видны независимо.

### Изменено
- **Обе тех-строки оверлея по умолчанию выключены** (ShowTimingLine и
  ShowQuestionTimingLine = false) — чистый оверлей из коробки; существующие
  config.json не трогаются.

## [2.27.2] — 2026-10-11

### Исправлено
- **Диаризация «умирала» после ~2 минут — всегда S1.** Очередь push'ей в
  Nemotron-стрим держала эпизод переполнения живым только до первого провала
  Count ниже Capacity: при ~33 push/сек очередь колеблется 512↔511, и сброс
  `_fullSinceMs` на каждом колебании навсегда глушил авто-ресинк (воркер
  продолжал принимать аудио в уже мёртвый стрим, метки замирали на S1).
  Теперь гистерезис: эпизод закрывается только когда очередь реально
  опустела ниже четверти ёмкости. Плюс worker склеивает накопленные 30-мс
  фреймы в один push (≤1с) — нативная цена вызова не зависит от длины,
  медленный бэкенд догоняет быстрее.
- **Инженерный режим: метки времени линейки налезали друг на друга.** Шаг
  подписей теперь считается от реальной ширины текста («HH:mm:ss» ≈ шире
  46px-предположения), на узком оверлее метки прореживаются skip-фактором,
  самая свежая (правая) подпись всегда видна.
- **Чип спикера S1/S2 сползал вниз.** У `TextBlock` внутри чипа стоял
  `LineHeight`, ломавший `VerticalAlignment=Center` — убран.
- **Кнопка «Открыть папку с логами» обрезала текст.** Снята фиксированная
  `Width=220` — автоширина по содержимому.

## [2.27.1] — 2026-10-11

### Исправлено
- **«[Динамик]» без S-меток и тишина на нестандартных маршрутах звука.**
  Если звук звонка шёл не на дефолтный эндпойнт вывода (Bluetooth-гарнитура,
  HDMI-монитор — обычно «Communications»-дефолт), loopback висел на тихих
  колонках: транскрипт пустой, диаризация молчит. Теперь захват ~раз в секунду
  сверяет метры всех активных render-эндпойнтов и при явном лидере пересаживается
  на него сам (только когда устройство не выбрано явно в настройках).
- **Watchdog рестартовал loopback на пустых пакетах тишины.** На idle-эндпойнте
  WASAPI штатно отдаёт `BytesRecorded==0` — это сон движка вывода, а не зомби.
  Теперь рестарт только когда метр эндпойнта реально шумит, а пакеты пустые
  (прод-кейс: 458 лишних рестартов за 26 минут тишины, каждый чистил очередь).

## [2.27.0] — 2026-10-11

### Добавлено
- **Оверлей: индикатор сквозного режима.** При включённом «Сквозном режиме»
  (Ui.ClickThrough) оверлей показывает баннер-подсказку с путём отключения —
  хоткей настроек и трей → Настройки → «Оверлей». Раньше при активном плаще
  не было никакого визуального намёка, почему «ничего не жмётся».

### Исправлено
- **Снятие галки «Сквозной режим» теперь отключает click-through вживую.**
  Раньше `ApplyUiConfig` не синхронизировал состояние плаща: стиль
  `WS_EX_TRANSPARENT` снимался только перезапуском приложения — пользователь
  снимал галку, жмякал «Сохранить», а клики продолжали проваливаться сквозь
  оверлей. Теперь состояние приводится к конфигу при каждом сохранении
  настроек (и наоборот — включённая галка надевает плащ без рестарта).

### Тесты
- **ButtonAuditScenario — фаза B2:** воспроизводит юзер-флоу «плащ активен →
  настройки → снять галку → Сохранить» и проверяет, что `WS_EX_TRANSPARENT`
  снимается без рестарта, баннер прячется и hit-test по кнопкам возвращается
  в оверлей. Фаза A проверяет видимость `CloakBanner` (через `CloakBannerBody` —
  Border не экспонирует AutomationId).
- **`--buttons-cloaked`:** принудительный старт аудита с плащом — фаза A всегда
  прогоняет симптом «ничего не жмётся» + баннер, независимо от `Ui.ClickThrough`
  в конфиге пользователя.
- **Hit-test по hwnd, а не по pid:** sibling-окна того же процесса (PreCallBrief,
  Owner=overlay поверх оверлея) съедают физический клик так же, как чужие окна —
  `MouseHitsOverlay` сравнивает hwnd оверлея и в отчёт пишет `hit→` окно-виновник
  (hwnd/pid/proc/title/rect).
- **Обход PreCallBrief:** `Memory.Enabled=false` на время аудита (бриф покрывает
  нижний ряд кнопок) + `CloseAuxWindows` с ретраями до 8 с на каждом старте
  приложения; клик по MemoryButton при выключенной памяти — SKIP.

## [2.21.2] — 2026-10-10

### Исправлено
- **Список пресетов промптов (вкладка LLM)**: убрано мёртвое пространство
  внутри карточки и обрезание последней строки. Причина: `DockPanel` с

  (на шкале аудио не было синего STT-столбика), и фраза терялась.
- Теперь два воркера: **STT-воркер** показывает реплику сразу (с плашкой «ожидание») и
  не блокируется, а **отдельный воркер ответов** (по одному, порядок диалога сохранён)
  догоняет ответом LLM и подставляет его в ту же реплику. Медленный/зависший LLM больше
  не стопорит показ распознанного текста. Подробный разбор — в истории коммита `fix(worker)`.
- **«Агенты промолчали» показывалось и на речь с микрофона** (которую агентам не отправляют
  по гейту «отвечаем собеседнику, не кандидату»). Теперь так помечается ТОЛЬКО реальное
  молчание агентов (их позвали, они смолчали); речь кандидата → нейтральное
  «🎧 ваша реплика — учтена в контексте».
- **Зелёный столбик шкалы** снова виден и означает **ответ LLM** (раньше в развязке гас
  мгновенно; и раньше означал «STT готов»). Синий = STT, зелёный = ответ пришёл.
- **Иконка окна настроек** — была дефолтная .NET-фиолетовая (app.ico не была ресурсом);
  теперь фирменный логотип.
- **«Проверить подключение» врало «ОК»** при рабочем ключе, но нерабочем чате: кнопка била
  только `GET /models`. Теперь делает РЕАЛЬНЫЙ чат-пинг выбранной моделью (ловит битую модель,
  политику free-моделей, лимиты) и **гасит залипшую плашку «ошибка LLM»** при успехе.
- **Реальная ошибка LLM в пузыре**: вместо общего «пустой ответ» показываем код+текст
  (401/402/404/429/сеть). При пустом контенте от reasoning-моделей — понятная подсказка
  (увеличьте лимит токенов / смените модель), а не «пустой ответ».
- **Индикация прогрева STT**: прогрев и так автоматический (синтетический сэмпл на старте),
  но теперь виден статус «⏳ Прогрев распознавания…» → «✓ Готово — говорите». Юзеру НЕ надо
  ничего говорить для «прогрева» и не надо смотреть в пустой экран.

### Исправлено (критично)
- **STT «переставал» распознавать через несколько минут разговора.** По логам с реальной
  сессии: за 6.5 минут нарезалось всего 8 чанков. Причина — агрессивные дефолты нарезки:
  **`MinSpeechMs=2000`** отбрасывал любую реплику короче 2с речи (в `AudioBuffer` —
  «suppressed too-short utterance»). На тихом/далёком микрофоне «длительность речи» = только
  громкие куски, поэтому нормальные реплики массово выбрасывались → казалось, что STT «встал»
  (красные столбики уровня есть, но чанк не набирается). Дефолты приведены к разумным:
  **MinSpeechMs 2000 → 400**, **SilenceSeconds 4.0 → 1.8**. Миграция (схема v4) чинит и
  существующие конфиги. (Диагноз подтверждён многоагентным разбором кода: баг не в стейт-машине.)

### Изменено
- **Мульти-агенты по умолчанию ВЫКЛючены у всех.** Экспериментальный режим интервью
  (агенты отвечают собеседнику, речь кандидата — только в контекст) на старых конфигах
  мог остаться включённым и путал: ассистент «молчал» на речь в микрофон. Разовая миграция
  (схема конфига v3) выключает его; включить обратно — галочка **Настройки → Агенты**
  (она рабочая и **применяется на лету**, без перезапуска). С выключенным мульти-агентом
  ассистент отвечает на всё и держит единую память диалога (в т.ч. для секретного канала).

## [2.5.2] — 2026-07-12

**Релиз стабилизации STT и инсталлятора.** Собрано по итогам двух раундов реального
теста на ноутбуке: распознавание больше не «залипает» при неготовом LLM, движок
распознавания переключается на лету, ошибки API видны в оверлее, а инсталлятор
(Lite ~517 МБ / Full ~1007 МБ) проверен сквозным автотестом через GUI-мастер
(установка → файлы → сброс конфига с бэкапом → удаление). Дефолт живого режима —
быстрый офлайн-GigaAM (~0.5с на реплику); Whisper остаётся для транскрибации файлов.

> Известное ограничение этого релиза: ответ LLM обрабатывается в одном воркере с STT,
> поэтому при медленном LLM показ реплик может отставать. Развязка STT↔LLM («река»)
> — в работе, отдельной веткой.

### Исправлено
- **STT переставал выводить текст через ~3 мин, если LLM не настроен.** Причина —
  `RateLimitSeconds=15` (пауза 15с между LLM-запросами) блокировала STT-воркер, очередь
  чанков (64) забивалась. Дефолт → **0**: воркер успевает, STT выводит текст непрерывно.
- **OpenRouter «не работал»** — по логам оказалось: при смене провайдера в поле модели
  оставалась локальная `qwen2.5vl:7b`, и OpenRouter отбивал её `400 "not a valid model ID"`
  (с валидной моделью — работал). Теперь смена провайдера приводит модель в соответствие:
  облачному — очищаем локальную (с подсказкой), локальному — ставим рабочий дефолт.
- Скорость: подтверждено замером — **GigaAM ~RTF 0.05** (быстро, ~0.5с на реплику).
  «Полминуты» — это Whisper на живых коротких репликах: сеть Whisper всегда кодирует
  окно 30с на каждый чанк (архитектура модели), поэтому ~12с/реплику даже на GPU и 30с+
  на CPU. Поэтому дефолт живого режима — GigaAM, а Whisper — для транскрибации файлов.
  Подробности и цифры: `docs/STT_BENCHMARK.md`.
- **`THIRD-PARTY-NOTICES.txt` реально попадает в установку.** Раньше ISCC молча не
  паковал файл по относительному пути `[Files]` — теперь он в общем свипе `publish\*`.
  Установка/сброс/удаление проверены автотестом через GUI-мастер (FlaUI), `docs/INSTALLER.md §12`.

### Добавлено
- **Прогрев STT** сэмплом на старте и при переключении движка — первая реальная реплика
  не платит цену холодного старта.
- **Уведомления при переключении движка**: «Переключаю…» → «Распознавание готово».

### Изменено
- **Whisper по умолчанию → GPU (Vulkan), если в системе есть любой GPU** (раньше — только
  дискретный; встройка шла на CPU). Дискретную предпочитаем.
- Сборка инсталлятора ускорена (lzma2/normal, без solid, многопоточно).

## [2.5.1] — 2026-07

Исправления по второму раунду теста (диагностика API-провайдеров).

### Исправлено
- **Ключ API не применялся** после ввода в настройках (уходил в запрос пустым → 401).
  Теперь Authorization берётся из конфига на каждый запрос — смена провайдера/ключа/модели
  работает без перезапуска.
- **Ошибки LLM/STT теперь видны в плашке** оверлея: реальный статус и текст
  (`401 Unauthorized: …`, `429 …`, таймаут) вместо общей фразы — юзер сразу понимает, что не так.
- Уведомление можно **закрыть**, и оно не всплывает снова по тому же компоненту, пока он не
  восстановится (X-кнопка сделана заметнее).

### Изменено
- **Движок распознавания переключается на лету** — без перезапуска (модель грузится в фоне,
  воркер подхватывает новый движок на следующем чанке).
- API-настройки: под полями BaseUrl/ключ/модель добавлены примеры значений.
- Full-инсталлятор: в мастере честно указано «GigaAM + Whisper» вместо только GigaAM.
